## 4. CORE PRODUCT REQUIREMENTS

### Module 1: Capture Engine
**REQ-CAP-001:** VS Code extension must capture accept events within 50ms with zero perceived latency impact on developer workflow.
**REQ-CAP-002:** Capture payload must include: file path, language, surrounding context (512 tokens), accepted text, rejection reason if available, session ID, timestamp.
**REQ-CAP-003:** All captured data stored in encrypted SQLite locally. Zero network transmission of raw code.
**REQ-CAP-004:** Git hook integration — PR merge events captured as high-confidence training signals (weight: 3x normal accept).
**REQ-CAP-005:** Test execution signals — if tests pass after an accepted suggestion, signal weight multiplied by 1.5 (RLVR approach).
**REQ-CAP-006:** Multi-editor support roadmap: VS Code (Day 1), JetBrains (Month 4), Neovim (Month 6), Zed (Month 8).

### Module 2: RAG Engine v2
**REQ-RAG-001:** cAST chunking mandatory — AST-boundary-aware chunking using Tree-sitter. No line-based chunking.
**REQ-RAG-002:** Hybrid retrieval — BM25 sparse + dense vector, combined via Reciprocal Rank Fusion (RRF).
**REQ-RAG-003:** Multi-view embedding — each chunk embedded from 3 views: code text, docstring/comments, function signature.
**REQ-RAG-004:** Code knowledge graph — call graph, import graph, inheritance graph extracted via Tree-sitter and stored.
**REQ-RAG-005:** Retrieval latency target: <200ms for 95th percentile on a 100,000-file codebase.
**REQ-RAG-006:** Incremental indexing — only changed files re-indexed on git commit hook.
**REQ-RAG-007:** Per-project isolated vector stores — teams cannot accidentally access each other's code.

### Module 3: Self-Learning Training Pipeline
**REQ-TRAIN-001:** Phase 1 (Month 1-3): QLoRA fine-tuning via Unsloth. Weekly scheduled runs.
**REQ-TRAIN-002:** Phase 2 (Month 4-6): GRPO layer via OpenRLHF. 2-GRPO minimum viable RL.
**REQ-TRAIN-003:** Phase 3 (Month 7+): SEAL dual-loop — inner SFT + outer RL. Self-generated curriculum.
**REQ-TRAIN-004:** MIT SDFT integration — catastrophic forgetting prevention. Replay buffer in every training run.
**REQ-TRAIN-005:** Hardware tiers: RTX 3090+ (full training), M2 Pro+ (MLX backend), CPU (inference only, cloud training queue).
**REQ-TRAIN-006:** Automatic rollback — if validation acceptance rate drops >10%, previous adapter auto-restored.
**REQ-TRAIN-007:** Training run max duration: 90 minutes. If exceeds, training paused and continued next scheduled run.
**REQ-TRAIN-008:** Synthetic augmentation — every accepted example generates 3-5 variations via local Ollama call.

### Module 4: Agent Interface
**REQ-AGENT-001:** Multi-provider support — Ollama, vLLM, SGLang, OpenAI API, Anthropic API, Groq, any OpenAI-compatible endpoint.
**REQ-AGENT-002:** Intelligent routing — task complexity classifier routes simple tasks to fast 7B model, complex to 70B.
**REQ-AGENT-003:** Test-time scaling (Month 6) — PDR+RTV framework for hard tasks. Multiple rollout candidates, tournament selection.
**REQ-AGENT-004:** MCP protocol support — community MCP servers connectable for additional tools.
**REQ-AGENT-005:** Tools: Bash execution, file read/write, git operations, test runner, linter, web fetch.
**REQ-AGENT-006:** gRPC headless mode for CI/CD pipeline integration.
**REQ-AGENT-007:** Streaming responses — first token within 500ms on local hardware.

### Module 5: Dashboard & Visibility

**REQ-DASH-002:** Training run history — loss curve, BLEU score, examples count, duration, adapter size.

## 7. RESEARCH FOUNDATION — PAPERS THAT PROVE THE THESIS

**Core Architecture:**
MIT SEAL (NeurIPS 2025) — Self-adapting LLMs via inner SFT + outer RL loop. Directly implements as Phase 3 training architecture.

LoRA (Microsoft Research, 2021) + QLoRA (UW, 2023) — Efficient fine-tuning on consumer hardware. Foundation of Phase 1 training.

GRPO (DeepSeek R1, 2025) + 2-GRPO — Group Relative Policy Optimization. Phase 2 training upgrade. No separate reward model needed.

SDFT (MIT, Feb 2026) — Sequential learning without catastrophic forgetting. 98% knowledge retention. Integrated in every training run via replay buffer.

RLVR — Verifiable rewards for code (code execution = binary reward signal). No human preference needed for reward signal.
