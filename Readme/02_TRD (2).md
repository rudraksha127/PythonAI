## 2. TECH STACK — EVERY CHOICE JUSTIFIED

### 2.1 Backend Core
**Language:** Python 3.12
**Why:** All ML libraries (PyTorch, HuggingFace, Unsloth, Tree-sitter bindings) are Python-native. Teri PythonAI expertise directly applies. FastAPI for web server.

**Framework:** FastAPI 0.111+
**Why:** Async by default, OpenAPI auto-generated, WebSocket support for streaming, pydantic v2 validation. 3x faster than Flask for concurrent requests.

**Database:** SQLite (encrypted via sqlcipher) → PostgreSQL (Supabase, scale)
**Why:** SQLite: zero-config, embedded, perfect for local-first tool. sqlcipher adds AES-256 encryption. Supabase PostgreSQL when multi-instance enterprise needed.

**Task Queue:** APScheduler 3.x (local) → Celery + Redis (enterprise scale)
**Why:** APScheduler handles weekly training cron with zero dependencies. Celery for enterprise when parallel training queues needed.

**Process Manager:** supervisord (Unix) / NSSM (Windows)
**Why:** ForgeAI server auto-starts on system boot. Crash recovery built-in.

### 2.2 Frontend
**Framework:** Next.js 14 (App Router) + TypeScript
**Why:** Server components for fast initial load. App Router for nested layouts. TypeScript for correctness in complex dashboard state.

**Styling:** TailwindCSS 3.4 + shadcn/ui
**Why:** shadcn components are copy-paste, not imported library — no version conflicts. Tailwind has zero runtime overhead.

**Charts:** Recharts 2.x
**Why:** React-native, responsive by default, accepts arbitrary data shapes. No D3 complexity.

**Code Editor:** Monaco Editor (same as VS Code)
**Why:** Syntax highlighting for 40+ languages. Diff view for before/after comparisons. Familiar UX for developers.

**State Management:** Zustand (light) + React Query (server state)
**Why:** Zustand: 1KB, no boilerplate. React Query: server state caching, background refetch, optimistic updates.

**Hosting:** Vercel (Free → Pro at scale)

### 2.3 VS Code Extension
**Language:** TypeScript
**Build:** esbuild (bundler), vsce (packager)
**Key APIs used:**
- `vscode.workspace.onDidChangeTextDocument` — detect file changes
- `vscode.commands.registerCommand` — accept/reject hotkeys
- `vscode.window.createWebviewPanel` — training status sidebar
- Interception layer: Listen to inline completion accept events from any installed AI extension (Copilot, Cline, Continue, Claude Code) via a universal event hook.

**WebSocket:** ws library. Connects to localhost:7337/ws/events. Sends events in real-time. Auto-reconnect on server restart.

### 2.4 Training Pipeline

**Phase 1 — Unsloth QLoRA:**
```
pip install unsloth unsloth_zoo
Base models supported: Llama-3.1, Qwen3-Coder, DeepSeek-Coder-V3, Phi-4
Training config:
  max_seq_length = 4096
  load_in_4bit = True (QLoRA NF4)
  r = 16 (LoRA rank)
  lora_alpha = 32
  target_modules = ["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"]
  per_device_train_batch_size = 2
  gradient_accumulation_steps = 4
  learning_rate = 2e-4
  warmup_steps = 50
  max_steps = 200 (per weekly run)
  optimizer = "adamw_8bit"
```

**Phase 2 — OpenRLHF GRPO:**
```
pip install openrlhf
2-GRPO format: pair (chosen, rejected) per step
Reward function: acceptance_signal × test_pass_signal × lint_clean_signal
No separate reward model (RLVR — verifiable rewards only)
Training: 100 steps per weekly run after QLoRA base
```

**Phase 3 — SEAL Dual Loop:**
```
Inner loop: Standard SFT on self-generated curriculum
Outer loop: RL reward = downstream acceptance rate improvement
Self-edit format: JSON instruction to training pipeline
Model generates: {"action": "generate_examples", "domain": "error_handling", "count": 50}
Outer loop trains model to generate better self-edits
```

**SDFT Replay Buffer (always active):**
```
Every training run batch composition:
  current_week_examples: 70%
  previous_week_examples (random sample): 20%
  foundational_examples (Month 1 anchor set): 10%
Purpose: Prevents catastrophic forgetting per MIT SDFT paper
```

### 2.5 RAG Engine v2

**cAST Chunker:**
```python
from tree_sitter import Language, Parser
# Languages: Python, TypeScript, JavaScript, Rust, Go, Java, C++, Ruby, PHP, Swift

def cast_chunk(code: str, language: str) -> list[CodeChunk]:
    parser = get_parser(language)
    tree = parser.parse(bytes(code, "utf8"))
    chunks = []
    for node in traverse_ast(tree.root_node):
        if node.type in SEMANTIC_NODE_TYPES[language]:
            # function, class, method, module — always complete
            chunk_text = code[node.start_byte:node.end_byte]
            if len(chunk_text) <= MAX_CHUNK_TOKENS:
                chunks.append(CodeChunk(text=chunk_text, node_type=node.type, ...))
            else:
                chunks.extend(split_large_node(node, code))
    return chunks
```

**Hybrid Retrieval (BM25 + Dense):**
```python
# Sparse: rank_bm25 library
# Dense: sentence-transformers/CodeBERT or voyage-code-2
# Fusion: Reciprocal Rank Fusion

def hybrid_search(query: str, project_id: str, k: int = 10) -> list[CodeChunk]:
    bm25_results = bm25_index[project_id].search(query, k=20)
    dense_results = chroma_client.query(query_texts=[query], n_results=20)
    fused = reciprocal_rank_fusion([bm25_results, dense_results])
    return fused[:k]
```

def scale_at_inference(prompt: str, model: LLM, budget: int = 5) -> str:
    # Parallel: Generate N rollouts
    rollouts = [model.generate(prompt) for _ in range(budget)]
    # Summarize each rollout to compact representation
    summaries = [summarize_rollout(r) for r in rollouts]
    # Recursive Tournament Voting
    winner_summary = rtv_select(summaries)
    # Sequential: Refine winner using PDR
    refined = pdr_refine(winner_summary, model, iterations=2)
    return refined.final_code

async def agent_loop(task: str, session: Session) -> AgentResult:
    memory = HermesMemory.load(session.project_id)
    while not done and steps < MAX_STEPS:
        thought = await model.think(task, memory, available_tools)
        action = parse_action(thought)
        observation = await execute_tool(action)

```sql
-- Core events table
CREATE TABLE events (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    session_id TEXT NOT NULL,
    project_id TEXT NOT NULL,
    event_type TEXT NOT NULL CHECK(event_type IN ('accept','reject','edit','pr_merge','test_pass')),
    file_path TEXT NOT NULL,
    language TEXT NOT NULL,
    context_before TEXT NOT NULL,  -- 256 tokens before cursor
    context_after TEXT NOT NULL,   -- 256 tokens after cursor
    suggestion_text TEXT NOT NULL,
    accepted_text TEXT,            -- NULL if reject
    edit_distance INTEGER,         -- how much dev changed accepted text
    weight REAL DEFAULT 1.0,       -- multiplied for high-signal events
    timestamp INTEGER NOT NULL,
    training_batch_id TEXT,        -- set when included in a training run
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Training runs table
CREATE TABLE training_runs (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    project_id TEXT NOT NULL,
    started_at DATETIME NOT NULL,
    completed_at DATETIME,
    status TEXT DEFAULT 'pending' CHECK(status IN ('pending','running','completed','failed','rolled_back')),
    phase INTEGER NOT NULL CHECK(phase IN (1,2,3)),  -- QLoRA, GRPO, SEAL
    examples_count INTEGER,
    training_loss_final REAL,
    validation_bleu REAL,
    acceptance_rate_before REAL,
    acceptance_rate_after REAL,
    adapter_path TEXT,
    adapter_size_mb REAL,
    rollback_reason TEXT,
    error_message TEXT
);

-- Acceptance rate tracking
CREATE TABLE acceptance_rate_snapshots (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    project_id TEXT NOT NULL,
    week_start DATE NOT NULL,
    total_suggestions INTEGER DEFAULT 0,
    accepted INTEGER DEFAULT 0,
    rejected INTEGER DEFAULT 0,
    acceptance_rate REAL GENERATED ALWAYS AS (
        CASE WHEN total_suggestions > 0
        THEN CAST(accepted AS REAL) / total_suggestions
        ELSE 0 END
    ) STORED,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Projects table
CREATE TABLE projects (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    name TEXT NOT NULL,
    repo_path TEXT NOT NULL,
    languages TEXT NOT NULL,   -- JSON array: ["python","typescript"]
    rag_indexed_at DATETIME,
    current_adapter_path TEXT,
    current_adapter_version INTEGER DEFAULT 0,
    training_schedule TEXT DEFAULT 'weekly',  -- 'daily','weekly','manual'
    training_phase INTEGER DEFAULT 1,
    base_model TEXT DEFAULT 'qwen2.5-coder:14b',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Sessions
CREATE TABLE sessions (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    project_id TEXT NOT NULL,
    editor TEXT DEFAULT 'vscode',
    developer_id TEXT,
    started_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_active DATETIME,
    suggestions_shown INTEGER DEFAULT 0,
    suggestions_accepted INTEGER DEFAULT 0
);

-- Indexes
CREATE INDEX idx_events_project_training ON events(project_id, training_batch_id);
CREATE INDEX idx_events_timestamp ON events(timestamp DESC);
CREATE INDEX idx_training_runs_project ON training_runs(project_id, started_at DESC);
CREATE INDEX idx_snapshots_project_week ON acceptance_rate_snapshots(project_id, week_start DESC);
```

## 5. SECURITY ARCHITECTURE

**Local data security:**
- SQLite encrypted with sqlcipher (AES-256-CBC)
- Encryption key derived from machine UUID + user passphrase via PBKDF2
- LoRA adapter files encrypted at rest
- API keys (Anthropic, OpenAI, Groq) stored in OS keychain (macOS Keychain, Windows Credential Manager, Linux Secret Service)

**Network security:**
- Local server binds to 127.0.0.1 only (not 0.0.0.0)
- HTTPS for all cloud API calls (TLS 1.3)
- WebSocket connections over WSS (local uses WS since loopback)
- JWT tokens for local authentication, 24-hour expiry, refresh tokens

**Cloud data policy:**
- Zero raw code ever transmitted
- Telemetry is opt-in, contains only numerical metrics
- Stripe handles all payment data (PCI-DSS compliant, ForgeAI never sees card numbers)
- User emails stored in Supabase (encrypted at rest, EU/US data residency options)

**Enterprise additional:**
- Air-gap mode: ForgeAI operates with zero internet dependency
- Private CA support for custom TLS certificates
- SAML 2.0 SSO integration
- Full audit logging to external SIEM systems via syslog/webhook
