━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FILE: api_dataset_gen.py

STRATEGY:
  Chunks = Reference Knowledge (what we know)
  APIs = Real Developer Experience (what they struggle with)
  LLM = Synthesis Engine (connect knowledge to experience)

STEP 1 — KEYWORD EXTRACTION:
┌─────────────────────────────────────────────────────────────┐
│ Input: chunk (title, text, codes, signatures)               │
│                                                             │
│ Extract:                                                    │
│   • Primary topic: "decorators"                            │
│   • Function names: "@functools.wraps", "@property"        │
│   • Related concepts: "closure", "higher order function"   │
│   • Error types: "RecursionError", "AttributeError"        │
│   • Version specific: "Python 3.2+", "deprecated in 3.11" │
│                                                             │
│ Tool: regex + frequency analysis (no LLM needed)           │
└─────────────────────────────────────────────────────────────┘

STEP 2 — STACK OVERFLOW MINING:
┌─────────────────────────────────────────────────────────────┐
│ API: api.stackexchange.com (free, no key for 300/day)      │
│ With key: 10,000 requests/day (free key)                   │
│                                                             │
│ Query: keyword + tagged:python + sort:votes                │
│ Get:   top 5 questions with accepted answers               │
│ Filter: 10+ votes only (quality filter)                    │
│                                                             │
│ What this gives us:                                         │
│   REAL questions from REAL developers                      │
│   REAL answers that ACTUALLY solved problems               │
│   Vote counts = community verified quality                 │
│   Comments = edge cases and gotchas                        │
└─────────────────────────────────────────────────────────────┘

STEP 3 — GITHUB CODE MINING:
┌─────────────────────────────────────────────────────────────┐
│ API: api.github.com/search/code (free token = 5000/hr)     │
│                                                             │
│ Query: keyword + language:python + stars:>100              │
│ Get:   real production code snippets                       │
│ Filter: repos with 100+ stars                              │
│                                                             │
│ What this gives us:                                         │
│   Code that actual users found useful (stars = votes)      │
│   Production patterns, not textbook examples               │
│   Edge cases handled by experienced engineers              │
└─────────────────────────────────────────────────────────────┘

STEP 4 — LLM ENRICHMENT:
┌─────────────────────────────────────────────────────────────┐
│ Input: chunk + SO Q&As + GitHub code                        │
│ Task: Create enriched training pair                        │
│                                                             │
│ Prompt strategy:                                            │
│   "Here is official Python documentation about X.          │
│    Here is a real Stack Overflow question about X          │
│    (with Y votes). Here is accepted answer.                │
│    Here is real GitHub code using X.                       │
│    Create ONE perfect training pair that combines          │
│    official accuracy with real developer context."         │
│                                                             │
│ APIs rotating: Groq → Cerebras → Together → Fireworks      │
│ Model: llama-3.3-70b (best free model)                     │
│ Fallback: If all fail → use chunk directly as pair         │
└─────────────────────────────────────────────────────────────┘

STEP 5 — HITL QUALITY GATE:
┌─────────────────────────────────────────────────────────────┐
│ Score 0-100:                                                │
│   +25: Has working code block                              │
│   +10: Code passes AST validation                          │
│   +20: Answer 200+ characters                              │
│   +20: No placeholder text                                 │
│   +15: Has explanation + reasoning                         │
│   +10: Mentions version or context                         │
│                                                             │
│ Score >= 70: Save to training_dataset.json                 │
│ Score 50-70: Save with flag (review later)                 │
│ Score < 50:  Retry with improved prompt (max 2 times)      │
│ Still < 50:  Use direct chunk format (guaranteed quality)  │
└─────────────────────────────────────────────────────────────┘
